# 05 — Rules for AI-assisted coding on this repo

## Always
1. Read `00`–`04` before changing anything.
2. Money changes only through the SQL RPCs. Never write `saldo`, ledger rows, or transaction status from Node, the browser, or ad-hoc SQL.
3. Prices come from the database. No price field in any request body.
4. One `reff_id` per purchase, generated by the database, reused on every retry.
5. Timeout / network / unparsed response ⇒ keep `PENDING`.
6. Refund only via `finalize_transaction_failed`, only on a confirmed failed signal.
7. Server secrets (`SUPABASE_SERVICE_ROLE_KEY`, `KHFYPAY_API_KEY`) stay in server-only modules; never `NEXT_PUBLIC_`, never logged.
8. Use `redactedUrl` for logging provider requests.
9. Schema changes go in a new numbered migration; add/adjust SQL tests for every new money path.
10. Browser Supabase queries list explicit columns and rely on RLS; admin data goes through the server.

11. Checkout never finalizes or refunds. Final states come only from `finalize_*` RPCs via a parsed + validated webhook or (after 2B) reconciliation.
12. Keep `POLICY` switches in `lib/transactions/policy.ts` off until real provider samples exist.

13. Only `sendIfClaimed` may call `/trx`. Never "read provider_attempts, then decide": claim first.
14. Admin mutations are single RPCs that re-check admin and write the audit log. Provider sync never writes `margin`, `is_active` or display metadata.
15. An empty form field is an error, never `0` (`z.coerce.number()` turns `""` into 0: pipe it after `z.string().min(1)`).

16. Credit a top-up only through `record_incoming_transfer` / admin RPCs. A callback authenticates first, then maps to `IncomingTransfer`; amount and bank_ref come from the verified payload, never from the user.
17. Bank account details live in `topup_banks` (admin-entered). Never put account numbers or bank credentials in code, docs, tests or chat.

## Never
- Invent KhfyPay fields, parameters or response shapes. Put gaps in `wire.ts`/`parsers.ts`/`webhook.ts` as TODOs.
- Replace the real provider with a mock in production code (test doubles belong in `tests/`).
- Process a callback twice by "deduplicating" in application code; the DB state machine is the guard.
- Add QRIS/payment-gateway code before the deposit stage is requested.

## Definition of done for a change
`npm run typecheck` · `npm run lint` · `npm test` · `npm run build` · SQL suite (`supabase/tests/run.sh`) when SQL changed · list of files changed · remaining TODOs that need information from the owner.
